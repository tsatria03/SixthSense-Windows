**Since 2026-09-24 the tests cannot write the real save.** `paths.user_dir()` uses `SIXTHSENSE_USER_DIR` when it is set, and every file in `tests/case/` imports `_scratch_save` right after its `sys.path` line, before any game code: it points that variable at a fresh `sixthsense_test_save_*` folder in `%TEMP%` and deletes it at exit. `save.py` sets the same variable per test. `paths.py`'s `test_every_test_file_keeps_off_the_real_save` fails if a test file lacks the import. Proved the same day: the whole suite ran with `APPDATA` pointed at an empty sentinel folder, 311 of 311 passed, nothing was written under the sentinel, the dev's `defaults.json` kept its timestamp, and no temporary save folder was left behind. **The tests are silent by themselves too (2026-09-24).** The dev heard NVDA say "debug" during a full run: debug mode's messages go through `st._say`, which fell back to the real `Speech.shared()` in the tests that give the stage no fake speaker (`input.py`, `gameplay.py`). The dev's rule: **testing must speak nothing whatsoever, wherever it is run from.** So `_scratch_save` also sets `SIXTHSENSE_SILENT=1`, which makes a `Speech` built without stand-ins load neither NVDA's client nor Prism and never speak or cancel speech (`speech.py`, `Speech.silent`), and forces `ALSOFT_DRIVERS=null`, `SDL_AUDIODRIVER=dummy` and `SDL_VIDEODRIVER=dummy`, so no sound and no window for NVDA to announce. All are set outright, overriding the shell. `speech.py`'s `test_the_tests_never_reach_the_players_screen_reader` and `paths.py`'s guard (every file imports `_scratch_save`, and all of `_scratch_save.QUIET` is in force) check it. Proved the same day: run from `%TEMP%` with none of those set by the shell and `APPDATA` at an empty sentinel, 313 of 313 passed, the sentinel stayed empty, the real save kept its timestamp. **How to run them now:** PowerShell, and skip `_*.py` when looping over `tests\case\*.py`, since `_scratch_save.py` is not a test. Setting the drivers or `APPDATA` in the shell is no longer needed; it does no harm. The history below is from before.

The tests in `tests/` write keys such as `TUTORIAL`, `COIN`, `GOLD` and the weapon keys through `UserDefaults`. That class saves to `%APPDATA%\SixthSense\defaults.json` (`paths.user_dir()` reads the `APPDATA` environment variable), which is the dev's real save. `test_gameplay.py` also opens a real OpenAL device and plays about 35 seconds of game audio, and the dev keeps NVDA running while working.

**Why:** Found during the 2026-09-21 evaluation. A plain run would have overwritten the dev's save and played audio over their screen reader.

**How to apply:** Since 2026-09-22 the dev lets Claude run the tests without asking ([[feedback_dont_run_or_build]]), but always like this. Until the repo has its own override (a `SIXTHSENSE_USER_DIR` variable read by `paths.user_dir()` and set by each test), run the tests like this, in PowerShell:
- set `$env:APPDATA` to a **fresh, empty** folder in the session scratchpad, new for each run. A save left over from an earlier run carries its settings in. On 2026-09-22 a reused save had `EYEMODE` "0", which is screen reader mode since `7c089b7`, and two `test_intro` earphone tests failed. The intro tests don't set the mode themselves.
- **Run the tests from the PowerShell tool, never the Bash one.** On 2026-09-23 a `$env:APPDATA=...` line went to Bash by mistake, where it is not an assignment, so `tests/case/intro.py` ran against the real `%APPDATA%\SixthSense` (the null driver was still set, so it was silent). The dev's `defaults.json` kept its earlier time and no `.bak` appeared, so nothing was written, but it was luck. In Bash it would be `export APPDATA=...`; simpler to keep test runs in PowerShell.
- set `$env:ALSOFT_DRIVERS = 'null'` so OpenAL Soft renders silently
- set `$env:SDL_AUDIODRIVER = 'dummy'`
- run each file as `python tests\case\<name>.py`; each is a plain script with its own `__main__` runner. Since 2026-09-23 the tests are in `tests\case\` without the `test_` prefix ([[project_tests_layout]]); the older runs below give the names they had then
